App QA Walkthrough

One run through the whole app, from inviting a teammate to closing a project. It covers everything since the September walkthrough: guided tours, help on every section, safer invites, the October audit fixes, time logging, and sprint velocity. Follow the parts in order, since each one sets up the next.

Team & settings Estimator Zoho CRM PBS billing Projects & board Workload & reports

What changed since the last walkthrough

  • Tours and help. Every page has a guided tour (the ? in the top bar), newcomers get a welcome and a Getting started checklist, and every section has its own ? that explains it in plain words.
  • Safer invites. The emailed link opens a page with a Continue button, so email scanners can't use it up. Admins can also hand out a password setup link from the Team page.
  • Projects come from estimates. New project is switched off, the New estimate dialog no longer picks a project, and an approved estimate is frozen: editing the project's tasks no longer changes the quote.
  • No PO without a deal. Create PO only appears once the estimate's Zoho deal is won.
  • Time logging. A task's logged total can't be typed over any more. Time is added with Add time or the timer, and deleting a task keeps the hours people logged.
  • Velocity and burndown. Each project page shows how many hours each sprint finished, the average pace, a finish forecast and a burndown. Reports has a Velocity column.
  • Fixes. Due dates save on the day you pick, sign-out clears the screen, completed projects leave everyone's workload, and on-time delivery uses the day a task was actually finished.

Before you start

  • Have four logins ready: an admin, a manager, a member and a viewer. Part 1 also needs a mailbox you can open for a new test invitee.
  • Use a test client in Zoho. Part 3 writes to the real CRM, and step 11 writes to real billing, which has no delete.
  • Name everything you create MY TEST …. On real projects and estimates, only look. If a dialog offers to change one, press Cancel.
  • Keep a phone, or a browser window narrowed to about 375px, for the checks at the end.

Part 1 — Invite a teammate

About ten minutes, as the admin. This creates the newcomer you'll use in Part 2.

01

Send an invite Team Changed

Team → Invite. Use the test mailbox, role Member.

EXPECT

The invite email arrives within a couple of minutes (check spam the first time). A dialog also shows a backup password setup link with Copy link, so you can send it by chat if the email is slow.

02

Accept it as the newcomer Team New

In a private window, open the link from the email.

EXPECT

A page asks you to press Continue. Nothing happens until you press it. Then you choose a password and land on the Dashboard, never on the home page.

Open the same email link again: it says the link has already been used or has expired, and how to get a new one.

03

The setup-link key button Team New

Back as the admin, Team → the key button on a pending invite's row. Then try the same button on someone who already has a password.

EXPECT

A pending invitee gets a fresh setup link to copy. Someone who already set a password is refused, because that link would sign its holder in as them.

Part 2 — Finding your way

About ten minutes, signed in as the new member from Part 1.

04

Welcome and the first tour Dashboard New

The Dashboard opens with Welcome to Timeline Estimator. Press Start the tour and step through it. While a step is highlighted, try clicking the highlighted button.

EXPECT

Each step points at a real control and explains it. Clicking the highlighted control does nothing, because tours only explain. Reload: the welcome doesn't come back.

05

Getting started checklist Dashboard New

Dashboard → Mine → the Getting started card. Press Show me on one item, then do what it asks (for example, upload an avatar in Settings).

EXPECT

Show me opens the right page and starts its tour at that step. Back on the Dashboard, the item you completed is ticked on its own. Items that don't apply yet ("Nothing assigned to you yet") never stop you reaching 100%.

06

Help on every section All pages New

On each page, click the ? at the top right of the page header and of each section. Then open the top-bar ? → Tour: … for that page.

EXPECT

Every ? opens a short plain-English explanation on click, phone included. Bold words have normal spaces around them (no "work?It isn't"). Member tours never mention buttons a member doesn't have.

Part 3 — From estimate to project

About thirty minutes, as the admin. The pricing run itself is unchanged from v2; these steps check what's new around it.

07

Create the estimate Estimator Changed

Estimator → New estimate. Title it MY TEST – walkthrough, then pick the client with Find in Zoho (a test company). Add three or four catalog tasks.

EXPECT

Platform starts on WordPress. The client can't be typed, and Create and open stays disabled until one is picked from Zoho.

The dialog has no project picker. In the editor's Setup tab, Internal project reads "None yet — Start project creates it" and can't be changed.

08

Generate line items asks first Estimator New

Scope & risk → Start guided scoping. Hover the (i) beside a few questions, then tap one on a phone. Answer a few questions, then Generate line items. Press Cancel on the dialog that appears.

EXPECT

Required questions carry an amber Required label and highlight until answered (then a green ✓), each section says how many are left, and on a phone the section circles show the count.

Every question has an (i) with a plain-English explanation. It opens on hover with a mouse and on tap on a phone; a second tap closes it.

Because the estimate already has lines, a Replace all line items? dialog asks first. Cancel leaves your catalog lines exactly as they were.

09

Set the details that carry over Estimator

Adjust tab → set the risk buffer to 20% and tick Requirements not pinned down. Note the timeline's launch date and one line's quoted hours.

EXPECT

The buffer moves only dates, and the box prices every line as Advanced. All three tabs say so.

10

No PO before the deal is won Estimator PBS Changed

Set the estimate's status to Approved by hand, without sending it to Zoho. Look for Create PO. Then set it back to Draft.

EXPECT

No Create PO button anywhere, because there is no Zoho deal to win yet.

11

Send, win, raise the PO Zoho PBS

Review → Send to Zoho. Then Estimator → Stages and move the card to Closed Won. Press Create PO and confirm.

EXPECT

On Closed Won the status flips to Approved on its own, and both Create PO and Start project appear. The PO number then shows on the card and in the header.

12

Start the project Estimator Projects Changed

Assign the teammate from Part 1 a work key so they get a task. Then Start project → Review schedule → Confirm & create.

EXPECT

The sprint dates match the estimate's timeline from step 9, buffer included. The project's own risk buffer reads 0%, because the estimate's buffer is already in those dates.

Each task's estimate equals its line's quoted hours (Advanced, from step 9), not the base hours.

Your teammate gets one notification, "… assigned you N tasks on "MY TEST …" — accept or decline", not one per task.

13

The approved estimate is frozen Projects Estimator New

On the new project, open a task and change its estimated hours. Then open the estimate.

EXPECT

One message says the estimate is approved and keeps the agreed price. The estimate's line and total are unchanged.

Part 4 — Working the board

About fifteen minutes, as the teammate (member), on the MY TEST project.

14

Accept the work Board

Click the notification from step 12. Open one of your tasks and press Accept.

EXPECT

The notification shows a real time ("just now"). Before you accept, the drawer has no Add time field. After you accept, it does.

15

Due dates land on the day you pick Board Fixed

Set a task's due date to the 15th of next month in the drawer. Check the card, then switch to List and Table.

EXPECT

Every view shows the 15th, not the 14th or the 16th. (If you can, repeat with your computer's time zone set ahead of and behind UTC.)

16

Log time Board Changed

In the drawer's Time tracking box, type 1.5 in Add time and press it. Then run the session timer for a minute and press Stop.

EXPECT

Logged total can't be edited by anyone, admins included. It grows by 1.5, then by the timer session. Workload → Mine → "Logged this week" grows by the same amounts.

17

Finish a task Board

Drag the task from step 15 by its grip handle to Done. Move a few other cards between columns too.

EXPECT

Cards move instantly and stay put after a reload, with no error page. The finished task leaves your Workload.

Part 5 — Tracking

About fifteen minutes, as the manager.

18

Velocity and burndown Project page New

Open the MY TEST project and scroll below the Timeline to the Velocity card. Then edit the sprint holding the task you finished in step 17 so it ended yesterday (move its start date back too if needed), and look again.

EXPECT

At first, Velocity and Forecast read "—" with "Shows once a sprint has ended", never 0. The burndown shows the sprint running today, and its line stops at today.

Once the sprint has ended yesterday, Velocity reads 0 h / sprint and Forecast says it needs a velocity first. That's correct: the task was finished today, after the sprint ended, and late work doesn't count for a sprint. The bar chart shows a Planned bar with no Finished bar.

Put the sprint's dates back. To see a real number, check a project with sprints that ended after work was finished in them.

19

The same numbers everywhere Workload Reports

Compare your teammate on Workload → Team, Dashboard → Team, and Reports. Check Reports' Velocity column for MY TEST.

EXPECT

Utilisation, overdue and pending counts agree on all three pages. Reports' Velocity matches the project page.

20

On-time uses the finish date Reports Fixed

Note the on-time delivery percentage on the Dashboard and in Reports. Rename the task you finished in step 17.

EXPECT

The percentage doesn't change. A later edit no longer counts as the moment the task was finished.

21

Finished projects leave the workload Workload New

As the admin, set the MY TEST project's status to Completed. Check Workload, both Dashboard views and Reports' Overdue.

EXPECT

The project's leftover open tasks no longer count toward anyone's load or the overdue figures. Set it back to Active afterwards.

Clean up when you're done

  • Set MY TEST back to Active if you left it Completed, then delete the MY TEST project and estimate (admin). Time you logged stays on your record, which is expected.
  • Team → deactivate, then delete, the test invitee. Remove any work key you added.
  • The Zoho deal and the PBS purchase order stay behind and need tidying by hand in those systems.

Found something? Note the step number, what you expected and what you saw, with a screenshot. If the page shows "This page couldn't load", open Error details on it (on a test copy) and include that too. Anything touching Zoho or PBS is a real write, so flag it rather than retrying.
