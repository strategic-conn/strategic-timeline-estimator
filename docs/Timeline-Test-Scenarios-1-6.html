Timeline Test Scenarios 1–6

Twelve client estimates arrive one after another. Each one becomes a project, so every new estimate is planned around the work the last ones already gave the team. Part 1 sets up the team and runs scenarios 1–6. Part 2 runs 7–12 and a final sweep.

Run this in demo mode, not the live app

Start project in the live app creates a real Zoho deal and a real PBS purchase order, and PBS can't delete a PO. Demo mode runs the same estimator and planner with everything kept in your browser: no Zoho, no PBS, no database.

  1. Stop any running npm run dev. Only one dev server can run per project folder.
  2. In a Git Bash terminal in the project folder, run:
    NEXT_PUBLIC_SUPABASE_URL= NEXT_PUBLIC_SUPABASE_ANON_KEY= npx next dev -p 3001
    Don't use PowerShell for this: setting a variable to "" there deletes it, and the app would load the live keys.
  3. Open http://localhost:3001/dashboard. The badge next to "Timeline Estimator" at the top of the sidebar must say Demo. If it says Live, stop: you're on the real database.
  4. To start over at any point: DevTools → Application → Storage → Clear site data for localhost:3001, then reload.
How to read a plan
  • Day 1 = the first working day on or after the day you run the scenario. Run scenarios 1–4 in one sitting so Day 1 stays the same.
  • Adjust tab → Who does the work shows the launch date. See who does what lists each task with its person, its dates and a reason (e.g. "Daniel · IT L1 · wordpress ★5 · 8h/day · after 17h already booked").
  • Start project → Review schedule shows the same plan before anything is created. Confirm & create makes the project. Its tasks then count as booked work for every later scenario.
  • Workload → Team shows each person's open hours. Check it after every Start project.

Check these on every scenario
  • No task starts or ends on a Saturday, a Sunday or a federal holiday.
  • No task starts or ends on a day its person has approved leave.
  • A person's tasks never overlap. The next one starts on or after the day the last one ends.
  • No unexplained gaps. An 8 h task for an 8 h/day person takes one day; for Ronel (6.4 h/day) it takes two.
  • QA starts on or after the day development ends.
  • An IT Level 2 task only ever goes to Daniel or Patrick.
  • The plan in Review schedule matches what the Adjust tab showed.

Every line item below is added on Line items → Add row: type the title, then open the row's details to set Role and Base hours. Tier stays Basic and Qty 1. The starter row has no title, so give it one or remove it; a row with no title creates no task.
